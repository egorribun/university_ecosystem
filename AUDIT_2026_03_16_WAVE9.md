### RZ-W9-01 · TOTP Replay Race Condition ✅ FIXED
**File**: `app/auth/mfa/totp.py:335–377`
**Severity**: CRITICAL
**OWASP**: A07 — Identification and Authentication Failures
**CWE**: CWE-362 (Race Condition)

**Problem**
`verify_totp_for_user()` prevented code replay via `last_used_code_hash`. However the check-then-update pair had no row-level lock on `MfaTotpEnrollment`. Two concurrent requests with the same TOTP code both read `hash=NULL`, both passed the replay check, and both set the hash — granting two logins from one code.

**Exploit timeline**:
```
T=0ms  Req A: SELECT enrollment → last_used_code_hash = NULL
T=0ms  Req B: SELECT enrollment → last_used_code_hash = NULL
T=1ms  Req A: hmac.compare_digest(NULL, hash) → False → PASS
T=1ms  Req B: hmac.compare_digest(NULL, hash) → False → PASS
T=2ms  Req A: enrollment.last_used_code_hash = hash  (commits)
T=2ms  Req B: enrollment.last_used_code_hash = hash  (commits — but already passed!)
```

**Before** (`totp.py:335`):
```python
if matched_enrollment is not None:
    code_hash = hashlib.sha256(code.encode()).hexdigest()
    if (
        matched_enrollment.last_used_code_hash is not None
        and hmac.compare_digest(matched_enrollment.last_used_code_hash, code_hash)
    ):
        raise_validation_error("errors.mfa.code_already_used", locale or "en")
    matched_enrollment.last_used_code_hash = code_hash
```

**After**:
```python
if matched_enrollment is not None:
    # RZ-W9-01: Acquire row-level lock BEFORE reading last_used_code_hash.
    # SELECT FOR UPDATE (nowait=False) serialises concurrent requests — the
    # second waits for the first to commit and then sees the updated hash.
    locked_result = await db.execute(
        select(MfaTotpEnrollment)
        .where(MfaTotpEnrollment.id == matched_enrollment.id)
        .with_for_update(nowait=False)
    )
    locked_enrollment = locked_result.scalars().first()
    if locked_enrollment is None:
        raise_validation_error("errors.mfa.invalid_code", locale or "en")

    code_hash = hashlib.sha256(code.encode()).hexdigest()
    if (
        locked_enrollment.last_used_code_hash is not None
        and hmac.compare_digest(locked_enrollment.last_used_code_hash, code_hash)
    ):
        raise_validation_error("errors.mfa.code_already_used", locale or "en")

    locked_enrollment.last_used_code_hash = code_hash
    locked_enrollment.last_used_at = _utcnow()
    matched_enrollment = locked_enrollment
```

**Why correct**: `SELECT FOR UPDATE` places an exclusive row lock that is held until the transaction commits. The second request blocks at the lock acquisition and, on unblocking, reads the already-updated hash and correctly raises `code_already_used`.

### RZ-W9-02 · NATS HMAC Timing Oracle ✅ FIXED
**File**: `services/ws-hub/pkg/hub/hub.go` (NATS message handler)
**Severity**: HIGH
**OWASP**: A02 — Cryptographic Failures
**CWE**: CWE-208 (Observable Timing Discrepancy)

**Problem**
NATS cache-invalidation message signatures were validated with Go's `!=` string operator. String comparison exits at the first differing byte (short-circuit), creating a timing oracle that leaks how many leading bytes match. An attacker able to send NATS messages and measure response latencies can recover the HMAC secret byte-by-byte.

**Before**:
```go
if payload.Signature != expectedSig {
    h.Logger.Warn("Invalid internal NATS signature — dropping event", ...)
    return
}
```

**After**:
```go
// RZ-W9-02: constant-time HMAC comparison via crypto/hmac.Equal
expectedSigBytes := hFunc.Sum(nil)
payloadSigBytes, decodeErr := hex.DecodeString(payload.Signature)
if decodeErr != nil || !hmac.Equal(payloadSigBytes, expectedSigBytes) {
    h.Logger.Warn("Invalid internal NATS signature — dropping event", ...)
    return
}
```

**Why correct**: `crypto/hmac.Equal` uses `subtle.ConstantTimeCompare` internally, which always runs for the full length of the shorter slice regardless of byte match position, eliminating the timing signal.

### RZ-W9-03 · GraphQL DB Error → Silent Anonymous Escalation ✅ FIXED
**File**: `app/graphql/schema.py:72–78`
**Severity**: HIGH
**OWASP**: A04 — Insecure Design
**CWE**: CWE-755 (Improper Handling of Exceptional Conditions)

**Problem**
`get_context()` wrapped the entire auth block in `except Exception`. A PostgreSQL connection-pool exhaustion error (e.g. `asyncpg.TooManyConnectionsError`) was silently swallowed, leaving `current_user = None`. The request continued as anonymous. During a connection-pool exhaustion event, every concurrent GraphQL request received an anonymous context — any resolver with a weak authorization check would return privileged data.

**Before**:
```python
except Exception as exc:
    from app.auth.security import SecurityError
    if not isinstance(exc, SecurityError):
        logger.debug("GraphQL auth fail: %s", exc)
    # Falls through → current_user stays None → anonymous context
```

**After**:
```python
except SecurityError:
    # Expected: bad/expired token, revoked session — silently anonymous.
    pass
except Exception as exc:  # noqa: BLE001
    # RZ-W9-03: Non-SecurityError (DB timeout, pool exhaustion) must NOT
    # silently demote the request to anonymous. Raise 503 so the client
    # retries and the operator sees the real error in logs/Sentry.
    logger.error(
        "GraphQL context: unexpected error during authentication — aborting request",
        exc_info=exc,
    )
    from fastapi import HTTPException
    raise HTTPException(status_code=503, detail="Service temporarily unavailable")
```

**Why correct**: Fail-closed principle — if the authentication layer cannot verify identity due to an infrastructure failure, the correct response is 503, not treating the request as anonymous.

### RZ-W9-04 · Anonymous CSRF Binding via IP+UA ✅ FIXED
**File**: `app/core/csrf.py`
**Severity**: MEDIUM
**OWASP**: A01 — Broken Access Control (CSRF variant)
**CWE**: CWE-352 (Cross-Site Request Forgery)

**Problem**
CSRF tokens for pre-login (anonymous) users were bound to `f"anon:{client_ip}:{user_agent}"`. Behind corporate NAT or a CDN, thousands of users share a single egress IP. Two users with the same IP and browser (Chrome on Windows 11 is the majority combination) received identical CSRF tokens. An attacker could use their own CSRF token to forge pre-login state-mutating requests on behalf of the victim.

**Before** (pseudocode from `_extract_session_id`):
```python
session_id = f"anon:{client_host}:{user_agent}"
```

**After**:
```python
anon_nonce = request.cookies.get(_ANON_NONCE_COOKIE_NAME, "")
if (not anon_nonce or len(anon_nonce) != _ANON_NONCE_HEX_LEN
        or not all(c in "0123456789abcdef" for c in anon_nonce)):
    anon_nonce = secrets.token_hex(16)
    setattr(request.state, _NEW_ANON_NONCE_STATE_KEY, anon_nonce)
session_id = f"anon:{anon_nonce}"
```
The nonce is issued as a short-lived `HttpOnly; SameSite=Strict; Max-Age=3600` cookie, giving every browser session a unique CSRF seed that survives across page loads without relying on IP or UA.

**OWASP**: A05 — Security Misconfiguration

**Problem**
`_enforce_production_secrets()` skipped the Elasticsearch password check entirely in `dev`/`staging`. A developer running a local ES instance without authentication would never see a validation error and would unknowingly expose an unauthenticated ES cluster.

### TD-W9-04 · Magic-Length UUID Validation in `_cast_id()` ✅ FIXED
**File**: `app/repositories/base.py:93–100`

**Problem**
`len(id_val) >= 32` is a magic constant. A 33-character opaque string (e.g. a session token accidentally passed as an ID) would attempt `uuid.UUID()`, fail silently, and be returned as-is — reaching the SQLAlchemy WHERE clause as a raw string, causing a cryptic `DataError` deep inside asyncpg.

**Before**:
```python
def _cast_id(self, id_val: Any) -> Any:
    if isinstance(id_val, str) and len(id_val) >= 32:
        try:
            return uuid.UUID(id_val)
        except (ValueError, TypeError):
            return id_val  # ← silent failure
    return id_val
```

**After**:
```python
_UUID_WITH_DASHES_RE = re.compile(
    r"^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$",
    re.IGNORECASE,
)
_UUID_HEX_RE = re.compile(r"^[0-9a-f]{32}$", re.IGNORECASE)

def _cast_id(self, id_val: Any) -> uuid.UUID | Any:
    if isinstance(id_val, uuid.UUID):
        return id_val
    if isinstance(id_val, str):
        if _UUID_WITH_DASHES_RE.match(id_val) or _UUID_HEX_RE.match(id_val):
            return uuid.UUID(id_val)
        raise ValueError(f"Invalid UUID format: {id_val!r}")
    return id_val
```

### TD-W9-06 · Dependencies Without Upper Version Bounds ✅ FIXED
**File**: `pyproject.toml`

**Problem**
`asyncpg`, `aiosqlite`, and `httpx` had no upper bounds. `asyncpg 1.0` is a planned breaking API overhaul; `httpx 1.0` introduces breaking transport changes. Renovate would auto-merge these during a CI run, breaking production without a human reviewer.

**Before**:
```toml
"asyncpg>=0.30.0"
"aiosqlite>=0.19"
"httpx[http2]>=0.27"
```

**After**:
```toml
"asyncpg>=0.30.0,<1.0"
"aiosqlite>=0.19,<1.0"
"httpx[http2]>=0.27,<1.0"
```

### PERF-W9-01 · N+1: User MFA Loading ✅ FIXED
**File**: `app/repositories/user_repository.py`, `app/models/user_loaders.py`
**Impact**: Doubled DB round-trips for 10–20% of users (those with MFA enabled)

**Problem**
`get()`, `get_by_email()`, `get_auth_by_email()`, `get_auth_by_id()` loaded a `User` in query 1, then conditionally called `ensure_mfa_relationships_loaded()` for query 2 when `user.mfa_required`.

**After**: Added `USER_AUTH_WITH_MFA_OPTIONS` in `user_loaders.py` combining all `joinedload` (1-to-1) and `selectinload` (1-to-N) options. All four auth methods now pass this option set unconditionally — a single query loads the user with all MFA relationships in one round-trip.

USER_AUTH_WITH_MFA_OPTIONS: tuple[Any, ...] = (

### PERF-W9-02 · N+1: Event Participant Counts via Correlated Subqueries ✅ FIXED
**File**: `app/repositories/event_repository.py:search()`
**Impact**: O(N) correlated COUNT queries per event row in search results

**Problem**
`participant_count_sub` was a correlated scalar subquery — PostgreSQL executed a separate COUNT for each Event row returned.

**Before**:
```python
participant_count_sub = (
    select(func.count())
    .where(models.EventAttendance.event_id == Event.id)
    .correlate(Event)
    .scalar_subquery()
    .label("participant_count")
)
```

**After**: Single aggregating CTE, one GROUP BY scan over `event_attendance`:
```python
participant_counts_cte = (
    select(
        models.EventAttendance.event_id.label("event_id"),
        func.count().label("cnt"),
    )
    .group_by(models.EventAttendance.event_id)
    .cte("participant_counts")
)
# LEFT JOIN to CTE in main query, using COALESCE(cnt, 0)
```

### PERF-W9-04 · Missing Composite Index for Message Pagination ✅ FIXED
**File**: `alembic/versions/202603160001_add_message_pagination_index.py` (new)
**Impact**: Sequential scan on `message` table for chat history pagination

**Problem**
The query `WHERE chat_id = X ORDER BY created_at DESC, id DESC LIMIT 50` had no covering index — PostgreSQL performed a full sequential scan per chat.

**After**: `CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_message_chat_pagination ON message (chat_id, created_at DESC, id DESC)`

This also enables keyset pagination:
```sql
WHERE chat_id = :chat_id
  AND (created_at, id) < (:cursor_ts, :cursor_id)
ORDER BY created_at DESC, id DESC
LIMIT 50
```

### PERF-W9-05 · Connection Pool Recycle 30min > Cloud Provider Idle Timeout ✅ FIXED
**File**: `app/core/config/database.py`
**Impact**: `asyncpg.ConnectionDoesNotExistError` on first request after low-traffic periods

**Problem**
`database_pool_recycle = 1800` (30 minutes). Most managed PostgreSQL providers (RDS, Cloud SQL, Supabase) close idle connections after ~10 minutes. Low-traffic overnight periods caused every pool connection to be severed by the provider before being recycled.

**After**: `database_pool_recycle = 540` (9 minutes — safely under the 10-minute threshold). `pool_pre_ping = True` was already set in `database.py` as a belt-and-suspenders health check at checkout time.

### PERF-W9-06 · ws-hub msgLimiters — Orphaned Entries on Crash ✅ FIXED
**Files**: `services/ws-hub/pkg/hub/hub.go`, `services/ws-hub/main.go`
**Impact**: ~100 KB/day memory leak at 10k connections/day with 1% goroutine crash rate

**Problem**
`msgLimiters` (per-client `rate.Limiter` map) entries are normally cleaned up via `defer` in `ReadPump()`. When a goroutine panics before the defer executes, the entry leaks permanently.

**After**: `StartLimiterCleanup(ctx context.Context)` launches a goroutine with a 5-minute ticker that cross-references `msgLimiters` keys against the active `h.Clients` map and deletes any entries for disconnected clients.

```go
func (h *Hub) StartLimiterCleanup(ctx context.Context) {
    go func() {
        ticker := time.NewTicker(5 * time.Minute)
        defer ticker.Stop()
        for {
            select {
            case <-ctx.Done():
                return
            case <-ticker.C:
                h.mu.RLock()
                active := make(map[string]struct{}, len(h.Clients))
                for id := range h.Clients { active[id] = struct{}{} }
                h.mu.RUnlock()
                h.msgLimiters.Range(func(key, _ any) bool {
                    if _, ok := active[key.(string)]; !ok {
                        h.msgLimiters.Delete(key)
                    }
                    return true
                })
            }
        }
    }()
}
```

## Section 4 — False Positives Identified

The following findings from automated subagent analysis were reviewed and **correctly rejected**:

| Claim | Verdict | Reason |
|-------|---------|--------|
| `safeSend()` race condition — defer/recover doesn't catch channel panic | ❌ False positive | `defer recover()` IS valid in Go for catching send-on-closed-channel panics within the same goroutine function body |
| `threading.Lock` fork-unsafe in Python | ❌ False positive | CPython creates per-process copies of `threading.Lock` objects on fork; lock state is not inherited |
| DI `AsyncIterator` missing `try/finally` in `fraud_detection_service` | ❌ False positive | `infrastructure.py:94–97` already has correct `try: yield ... finally: await client.close()` |
| JWT `kid` fallback allows token bypass | ❌ False positive | Code already rejects tokens without `kid` at lines 607–612 |
| `news_repository.list_news()` N+1 scalar subquery | ❌ False positive | `list_news()` uses `asyncio.gather` batch fetch pattern — not correlated subqueries. Only `get_analytics_data()` uses scalar subqueries (acceptable for one-time full-table analytics) |
