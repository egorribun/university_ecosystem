# Licensing audit — 2026-11-06

## Result and scope

The technical inventory covers project notices and documentation, all tracked
package manifests/locks, bundled assets/reference material, dependency license
evidence, and the declared distribution paths. Confirmed metadata, notice,
attribution and packaging contradictions are repaired by this change.
**This is not a finding that every component has cleared rights or that the
whole product can be exclusively restricted.** The open items below remain
material to redistribution and branding.

The development baseline is the merge of [PR #1361](https://github.com/egorribun/university_ecosystem/pull/1361).
The default-branch comparison is the merge of [PR #1362](https://github.com/egorribun/university_ecosystem/pull/1362).
Both license transitions were merged by the owner. This follow-up targets
`egorribun`, as required by the repository workflow; it does not import the
development code into `main`, update a deployed website, or certify either
branch's full CI. The branches have materially different dependency graphs.

The GitHub repository API identifies the default-branch notice as `Other` /
`NOASSERTION`, consistent with a custom notice. The repository description and
topics do not claim a standard open-source license; the explicit README badge
links to the applicable project terms.

The initial tracked-file inventory contains 5,502 files, 30 manifests (11 npm,
7 Cargo, 10 Go and 2 Python), 16 standalone license/notice files, 154 reference
skill directories and 152 asset/archive paths. Counts describe that baseline,
before the new notices and reports in this change. Text searches covered
license/copyright/public-inspection/open-source assertions and copied-source
markers; historical dated evidence was preserved rather than rewritten as a
current claim. The inventories identify their evidence and scope; a filename
or metadata label is not proof of ownership.

## Package graphs and evidence

### npm and browser assets

The frontend manifest declares 56 direct runtime and 98 direct development
dependencies; `main` declares 56 and 91 respectively. These counts are package
names in the manifests, not lockfile install paths. The development frontend
lock contains 2,377 package paths. Root and frontend locks were inspected
separately, including local file targets, links, optional/platform entries,
license expressions and installed legal files. A dependency selected by a
runtime package graph is not necessarily executed in the browser: the graph
also contains SSR/build infrastructure and optional native bindings.

The root lock contains 306 effective package paths (290 package/version
identities). The frontend lock contains 1,644 distinct package/version
identities across its 2,377 paths; 2,144 paths are installed on this host.
The three root and seven frontend license-field omissions are local links,
whose resolved targets have their own license metadata. An additional stale
root entry is marked `extraneous` with no installed version and is excluded
from those dependency counts. `config-chain`'s old npm license-object shape
and its lock's `MIT` string denote the same license, not conflicting grants.

The frontend production dependency closure contains 527 lock paths and 451
distinct package/version identities, including one local WASM package. Full
texts and exact-version source evidence are retained in the public JavaScript
notices; any unresolved text/provenance evidence is identified in the source
index, rather than replaced with a guessed license. Full texts cover 371 of
376 installed third-party versions; `bytewise 1.1.0`, `err-code 3.0.1`,
`get-browser-rtc 1.1.0`, `nostr-wasm 0.1.0` and `typewise 1.0.3` still lack a
located full copyright/grant text. All five declare MIT in metadata.
Another 74 optional/platform versions are absent from the Windows install.
Missing optional bindings
on Windows were distinguished from missing metadata. Selected Linux binding
tarballs were inspected without executing their scripts. Registry source
artifacts were checked against their lock integrity before use.

The Fontsource Inter and Outfit license texts and the existing bundled Inter
notice are provided separately. The map attribution follows
[OpenFreeMap's credits](https://openfreemap.org/) and links
[OpenStreetMap's copyright information](https://www.openstreetmap.org/copyright).
University marks, background imagery and generated icons that incorporate
third-party branding do not gain a rights grant through these notices.

### Python

`uv.lock` contains 236 package records: 234 registry packages and two workspace
records. The Python 3.14 platform-selection union has 149 registry runtime
packages; 148 have full legal-text evidence, while `clamd 1.0.2` remains open.
Development/group-only packages are listed separately in the complete locked
inventory. Exact installed artifacts were used where their name and version
match. Missing Unix variants were checked against the lock-pinned sdists;
missing notices were recovered from version-bound official source trees.

MPL applies to `certifi`, `py-vapid`, `pywebpush`, and covered portions of
`orjson 3.12.0`. orjson's expression is
`MPL-2.0 AND (Apache-2.0 OR MIT)`, not simply MIT/Apache. Its exact source archive
contains vendored Rust crates with additional notices, recorded with the
Python distribution evidence. `psycopg`/`psycopg-binary` have LGPL and bundled
library obligations. The source-access index supplies exact sources and
identifies these obligations; installed dependency license directories are
preserved in the copied virtual environment. The project license does not
restrict source access, modification or replacement rights granted by those
component licenses. This inventory is not a rebuild/certification of every
third-party binary wheel on every platform.

All seven Cargo locks contain 557 records and 215 distinct package/version
identities. Production graphs were target-filtered, separating runtime-linked,
build/proc-macro and development/test paths; a descendant of a build-only node
stays build-only unless also reached through a runtime path.

The Windows native target also has 28 runtime crates, with 27 common to Linux.
Linux adds `iana-time-zone`, Windows adds `windows-link`; the native wheel's
notice/source corpus retains their 29-crate union, with 10 build-only crates
on each target.

Each included crate/version was checked against its Cargo lock. Original
legal-file bytes are retained. `cssparser 0.38.0` and `dtoa-short 0.3.5` require
MPL notices/source access in the sanitizer distribution. SPDX `OR` denotes a
choice of grants; `AND` retains cumulative obligations. Build/test exclusions
from runtime bundles do not erase those components from the full inventory or
their licenses from source/developer distributions. See Mozilla's
[MPL distribution guidance](https://www.mozilla.org/en-US/MPL/2.0/FAQ/).

Rust 1.99.0 `core`, `alloc`, `std` and compiler-builtins notices are retained
separately from the Cargo dependency counts. The artifacts include original
MIT/Apache, LLVM-exception and Unicode text bodies and the byte-exact
release-generated library copyright record (retained under a text filename).
The latter covers release-wide library dependencies across targets; it is not
presented as a narrower per-artifact standard-library link closure. Its source
index records that boundary. The compiler/tooling-wide notice corpus is not
misidentified as product runtime code.

The generated WASM binaries were rebuilt with the pinned Linux toolchain and
compared with the pre-audit bytes: the binary bytes are unchanged. Legal inputs
are now bound into the existing source provenance along with the generated
package legal files and npm allowlists. Consumers still validate provenance;
Docker does not regenerate it to accept a different build.

## Verification and maintenance

Run the relevant package license checks, source provenance and npm packing
tests after any lock or legal-input change. Recompute the actual Go target
closure and regenerate notices when imports, build tags, probe pins or
toolchains change. For Python, preserve installed license files and inspect
native/vendored components in the selected artifacts. Check browser notices
and source URLs alongside font/map/provider changes. New source or asset
imports require provenance and retained notices at review time.

## Post-publication CI follow-up

The first [hosted CI run](https://github.com/egorribun/university_ecosystem/actions/runs/42159224430)
for PR #1364 ended with failures that included regressions from this change.
They are not classified as unrelated baseline failures. The follow-up repairs:

- Canonicalize the generated npm `files` allowlist after license finalization.
  Real Docker and mounted-host builds enumerated the same extra license files
  in different orders. Only the two generated `package.json` files differed;
  binaries and legal bodies were identical. Sorting/deduplicating this set
  makes all 20 exported Docker package files match source provenance exactly.
  The actual Docker install-stage verifier now passes before npm installation.
- Move provider/OSM credits entirely into the locale catalogs. The i18n scanner
  correctly rejected raw provider labels and a literal translation fallback.
- Update valid adversarial fixtures to provide all 18 canonical source inputs,
  while retaining rejection of changed legal inputs and the no-rebuild rule.
- Update Docker topology contracts for the Node license-finalization stage and
  mirror the seven missing legal-file inputs in the test Docker ignore.
- Preserve npm 11.17's property order for the newly licensed local clone lock
  record. The isolated lock generator produced semantically identical JSON,
  but moving `license` before `engines` is necessary for its strict zero-text-diff
  already-final proof. Generator logic and graph acceptance remain unchanged.

The corrected local cohorts passed: 107 focused Node contracts, 45 Python
Docker/quality contracts, 48 map/footer cases, i18n validation (18 translation
cases plus 32 scanner cases), ESLint, formatting and TypeScript. The full local
Windows Node cohort reported 970 passes, 6 MapLibre fixture failures and one
skip; no full Windows-suite success is claimed. Its MapLibre modules are outside
this licensing repair. Fresh hosted outcomes remain source-specific and must
be checked on the current PR head. The original image-scan and live-Core failures
both stopped at the same generated-package provenance mismatch; downstream
backend summary/CI-success failures also do not constitute independent passing
or failing evidence after the repair.
