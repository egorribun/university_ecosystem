This inventory records upstream application terms; it does not claim that every OCI layer, base OS package, or bundled component has been examined.

## Vendored NATS Helm chart

The archive [`charts/university-ecosystem/charts/nats-2.15.0.tgz`](../../charts/university-ecosystem/charts/nats-2.15.0.tgz) is the NATS `nats-2.15.0` Helm chart, separate from the `nats:2.15.0-alpine` server image. The parent chart and lock file name the official NATS Helm repository. Its official index maps chart 2.15.0 to the GitHub release archive; the vendored archive matches that official archive digest. Comparison against the exact tag source tree found 53/54 files byte-identical. `Chart.yaml` alone was normalized during packaging (description wrapping and metadata ordering; chart identity/version fields unchanged). The tag's `nats-io/k8s` root license is Apache-2.0, but the chart archive omits a license file. [the retained chart notice](distribution/NATS-CHART.txt) contains the verbatim tag license text to accompany redistribution. The archive and tag comparison were performed read-only; the official NATS archive is unchanged. The retained notice is also shipped inside the parent chart as `THIRD_PARTY_NOTICES.txt`.

The local Redis compatibility chart archive is the repository's own `file://../redis-compat` chart (five original source files; project notice added by this audit), not upstream Bitnami. It follows the repository's first-party license transition; its `redis:7.4.11-alpine` runtime image has separate upstream terms.

## Scope limit

The inventory also records three image defaults inside the original NATS
chart: config reloader 0.23.0, Prometheus NATS exporter 0.20.1 and nats-box
0.19.7. Their upstream projects have Apache-2.0 source evidence; image build
mapping/layers remain unverified. Parent values disable all three, so their
presence in the archive is not a claim they are active services.

The image inventory records image names/tags, with the exact OCI pins retained at the referenced declarations, with roles and repository-relative source locations. Image digests identify content-addressed OCI artifacts; they do not by themselves identify complete source builds or enumerate all licenses in their OS layers. Treat these records as upstream project-license evidence, not a full OCI/SBOM review or a compatibility/violation finding.
