### SW2 Decision (committed `chore(wave141-sw2-temporal-yaml-verified)`)

**Scenario A confirmed** with key REVISION from original Agent 2 plan:

The canonical `config_template.yaml` only supports `cassandra`, `mysql8`, `postgres12`, `postgres12_pgx` databases — **NOT SQLite**. Agent 2's "embedded SQLite via `temporalio/server`" recommendation would require bypassing the templated YAML rendering entirely (custom `docker.yaml` mount + manual `temporal-sql-tool` schema bootstrap).

**Pivoted path: `temporalio/auto-setup:1.30.2` with PostgreSQL backend**:
- Leverages existing `postgres` service in `docker-compose.full.yml`
- `auto-setup` bundles schema migration + namespace bootstrap
- Auth via env vars alone — NO custom YAML mount required (simplifies SW3)
- `depends_on: postgres: service_healthy` extends naturally

**Env vars for SW3 docker-compose**:
- `DB=postgres12` + standard `POSTGRES_*` connection vars
- `TEMPORAL_JWT_KEY_SOURCE1=http://backend:8000/.well-known/jwks.json`
- `TEMPORAL_AUTH_AUTHORIZER=default`
- `TEMPORAL_AUTH_CLAIM_MAPPER=default`

**Implications for SW3-SW5**:
- SW3 simpler than original plan (NO `config/temporal/auth_config.yaml` file; pure docker-compose env block)
- SW4 service token MUST mint JWT with `sub=file-processor-service` (Issue #8218 mitigation)
- SW5 unchanged (`client.NewAPIKeyStaticCredentials(cfg.TemporalAPIKey)`)
