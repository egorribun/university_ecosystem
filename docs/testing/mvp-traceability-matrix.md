# MVP Block 4 traceability matrix (ТЗ §2–13)

Date: 2026-11-14. Verified against source. Local-only checks are identified
in individual evidence cells; they are not hosted acceptance. Results are
filled only from hosted CI runs on `main`; the "Result on SHA" column is
empty by design.

## Scope

This matrix maps each applicable item of the MVP technical specification
(`docs/superpowers/plans/University_Ecosystem_MVP.md`, sections 2–13) to the
automated scenario that confirms it, the lane and browser matrix the scenario
actually runs, and the gaps that remain. It is the Block 4 evidence index for
the MVP stage-3 acceptance in `docs/superpowers/plans/MVP_MASTER_PLAN.md`
("Traceability ТЗ 2–13; реальный Chromium, mocked Firefox/WebKit").

Sources:

- ТЗ: `docs/superpowers/plans/University_Ecosystem_MVP.md`, sections 2–13.
- Plan: `docs/superpowers/plans/MVP_MASTER_PLAN.md`, stage 3 and Block 4
  (RU/EN and viewport policy, area bullets, acceptance).

How this was verified: every cited test title was matched by text search
against the cited spec file on 2026-11-14, and each title was checked to
exist in the stated lane. Assertion bodies were read for every row whose
grade changed in this revision and for every negative claim ("none found").
Other FULL grades rely on the assertion bodies read for the earlier draft.
Mechanical title checks cannot prove that an assertion is strong enough, so
a grade describes what the cited test asserts, not whether it passes.

Scenario cells give the path from the repository root, with the exact test
title. Titles with `${...}` are templates generated by a loop; the values
are stated in the Run matrix column.

## Status legend

- **FULL**: an assertion covers the requirement in the lane that matters.
  Delivery, authentication, permissions, Web Push and realtime behaviour
  require the live lane.
- **PARTIAL**: an assertion covers part of the requirement, or only one
  width, locale or theme, or only unit or static checks.
- **NONE**: no test found for the requirement.
- **n/a**: a process item, not a product scenario. It is handled in
  "Manual checks" or by the quality gates.

Redesign clauses (for example "полный UI/UX редизайн") are graded on their
testable behaviour. The aesthetic judgement is listed in "Manual checks".

### Product gap (not a test gap)

- **Event and group relationship synchronization (§4 «Мероприятия»).**
  PR #1399 adds backend request-path creator, attendee and group membership
  writes, with backend tests. Teacher create/edit/delete still needs exact-SHA
  hosted live evidence at 390 and 1440 in RU. This source fix is not a complete
  synchronization guarantee. The source now protects both HTTP event-file
  read routes with a fresh primary-database attendance check: after that read
  observes a committed cancellation, stale attendee tuples or cached `view`
  grants alone cannot authorize file access. Independent graph grants remain.
  The [ADR-008 event-file guard](../adr/ADR-008-spicedb-rebac.md#2026-11-14-event-file-membership-guard)
  does not retract in-flight reads, reconcile stale tuples, make writes durable
  or close group synchronization gaps. TOUCH-only backfills do not remove stale
  relations. Exact-schema, current-source PostgreSQL/RLS and deployed-reader
  evidence remain separate acceptance requirements; source presence is not proof.

- **HTTP 500 recovery has bounded implementation, not browser acceptance (R67).**
  `frontend/src/pages/NewsDetail.tsx` now offers localized retry for terminal
  HTTP >=500 errors, retaining Back and the existing query retry policy.
  Authenticated Axios and anonymous status-bearing errors are covered by real
  Query/MSW tests in jsdom, including persistent failure, duplicate activation,
  successful recovery, missing articles and navigation away.
  `frontend/scripts/server-prod.mjs` emits standalone localized HTML with a
  same-location retry when a renderer throws before headers on GET; HEAD has
  an empty body and non-GET/HEAD failures remain plain text. The Node subprocess
  test exercises the actual wrapper and its retry script through JSDOM/vm,
  not a real browser. Normally returned `Response(500)` bodies and stream
  failures after headers retain their prior behavior. Other API error surfaces
  are not covered by this NewsDetail fix. Genuine browser/mobile/accessibility
  and current-source hosted evidence remain open; no universal 500 handling
  or deployed acceptance is inferred.
