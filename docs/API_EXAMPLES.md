# API Examples

Examples below follow the OpenAPI contract generated by the running FastAPI
application.  Re-check `/api/openapi.json` when adding fields; tokens are never
returned in JSON and are stored in an HttpOnly cookie.

## Authentication

### JSON login

```http
POST /api/v1/auth/login/json
Content-Type: application/json

{"email":"student@university.edu","password":"SecurePass123!","trust_device":false}
```

Successful login returns `200 OK` with the authenticated user payload and sets
the access/refresh cookies.  Do not read or persist an `access_token` field from
the response.  An MFA challenge returns `202 Accepted`:

```json
{
  "status": "mfa_required",
  "user_id": "uuid",
  "session_id": "uuid",
  "default_method": "totp",
  "methods": [{"method": "totp", "challenge_token": "..."}]
}
```

The form-compatible endpoint is `POST /api/v1/auth/login` with
`application/x-www-form-urlencoded` fields `username`, `password`, and optional
`trust_device`.

### Register

```http
POST /api/v1/auth/register
Content-Type: application/json

{"email":"newuser@university.edu","password":"SecurePass123!","full_name":"Jane Smith"}
```

The response is a small registration acknowledgement, for example
`{"status":"registered","id":"<uuid>"}`.  Authenticate separately with
the login endpoint.

## Events

### List events (cursor pagination)

```http
GET /api/v1/events?limit=20&cursor=20
Cookie: access_token=<HttpOnly cookie>
```

```json
{
  "items": [{"id":"<uuid>","title":"University Festival","starts_at":"2026-12-30T10:00:00Z"}],
  "total": 45,
  "limit": 20,
  "cursor": "20",
  "next_cursor": "40",
  "has_more": true
}
```

### Attendance

```http
POST /api/v1/events/attendance
Content-Type: application/json
Cookie: access_token=<HttpOnly cookie>

{"event_id":"<uuid>","qr_token":"<signed-token>"}
```

## Notifications

```http
GET /api/v1/notifications?limit=20&cursor=0
Cookie: access_token=<HttpOnly cookie>
```

The response uses the same cursor shape (`items`, `total`, `limit`, `cursor`,
`next_cursor`, `has_more`).  Use `POST /api/v1/notifications/read-all` or
`POST /api/v1/notifications/{notif_id}/read` to update read state.

## Common errors

```json
{"detail":"Invalid credentials"}
```

`401` means the authentication cookie is missing/invalid, `422` is request
validation failure, and `429` includes a `Retry-After` header.
